# 长任务经验学习

深度模式在每个有实质产出的循环结束时做一次简短经验归总，但不因此机械创建 `lessons.md`。只有已经出现有证据支撑、未来可能复用的内容时，才创建或更新该文件。

快速模式默认不创建经验文件；用户明确要求，或任务出现可归因的失败、错误假设或有效恢复策略时，可以按需增加。

## 记录范围

只记录：

- 用户纠正并得到验证的规则；
- 可避免的失败或阻碍；
- 被证伪的关键假设；
- 有效且可复现的恢复方法；
- 反复出现的流程摩擦；
- 效果已经通过实例或测试验证的工作方式。

不要记录一次性流水、普通完成事项、未经验证的感想或实时执行状态。

## 分类

- **仓库规则**：只对一个仓库稳定成立，可作为其 `AGENTS.md` 候选。
- **全局偏好**：跨项目稳定成立，可作为全局 `AGENTS.md` 候选。
- **可复用事实或经验**：可作为 Memory 候选，但受平台的显式授权规则约束。
- **待验证候选**：已有证据但复用价值尚未验证，可以暂存并标记 `pending`。

不要创建 `USER.md`，它会与全局指令和 Memory 重复。

普通一次性观察只留在当轮进度小结或 `state.md`，不进入 `lessons.md`。

## 提升门槛

goal 完成时可以自动整理候选，但不能自动提升。每个候选应写明：

- 建议规则；
- 适用范围与不适用情况；
- 支撑证据；
- 验证方法；
- 当前状态。

在用户明确接受前保持 `pending`。接受后先检查目标位置是否已有重复或冲突，只做最小修改，并用代表性实例或 eval 验证。验证后才能标记为 `promoted`。

修改仓库或全局 `AGENTS.md`、写入 Memory，都需要用户另行明确授权。被拒绝或尚不稳定的候选可以保留，但不能当作未来任务的既定规则。
