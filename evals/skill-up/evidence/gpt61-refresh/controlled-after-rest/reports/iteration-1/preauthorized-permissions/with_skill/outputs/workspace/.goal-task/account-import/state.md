## 执行、重排与恢复契约

- 按模块、根因或验证面分批，先核查已有路径再修改。冻结一批后运行受影响检查；阶段边界或新风险出现时再扩大集成、包级和浏览器验证，保留断言、阈值和退出码，不为绿灯降低标准。
- 默认每项最多尝试 3 次；每次记录错误、证据、恢复条件和依赖。随后把该项及其依赖移至可独立工作之后，标记 waiting/deferred/needs-input；条件变化或阶段边界再检查，不豁免验收门禁。
- 浏览器、CI、下载或 review 等待期间，推进不冲突的可用工作，例如已有输入下的解析/校验修复、相应测试、文档、调用链核查或验收准备。缺项目时只做有意义的准备，不伪造功能或制造忙碌。
- 并行前明确统一结果、输入依赖、独占文件所有权及集成负责人；锁文件、schema 和共享接口由单一负责人维护。告知 worker 不独占代码库，不覆盖他人改动。集成负责人验证合并后的实际 diff，worker 的局部通过不算整体验证。
- 默认 3 名独立只读 reviewer 在重大行为变更里程碑及最终集成检查整合 diff；实现者不算独立 reviewer。结论包含严重性、准确位置、观察证据和建议；修复后复审，默认最多 3 轮修复/复审，仍未解决则记录并重排，不宣称通过。reviewer 不可用时推进独立工作并保留门禁，不以自审替代。
- 本地持久里程碑在适用验证/审查通过后提交，不创建空提交、不覆盖用户改动。必要的中间 checkpoint 可明确记录未通过门禁，不冒称已验收。本任务已明确授权 push/PR，核实目标后执行；远程 PR review 后的修复须重新验证、复审，再推送并核实最新 head。
- 每个有效循环后简报已完成及证据、剩余门禁和一个主要下一步。无明确分母不报告百分比，所有门禁通过前不报告 100%。里程碑提交后记录 commit 及实际完成范围。
- 压缩上下文、交接、配额等待前 checkpoint：已完成/剩余、最新 commit、未提交改动、验证与审查证据、活动等待、恢复条件和一个下一步。恢复时对照 checkout 与证据核验状态，不靠重建聊天记忆，也不重复全部初始化。
