1. 引入并实际调用一个适用的认证依赖，实现 Authorization Bearer token 的解析和有效性验证。可信凭据来源与返回接口需明确；移除硬编码测试凭据，不接受任意非空 token。

3. 用可执行行为测试覆盖有效 token、无效 token、缺失头、错误认证方案、空值及畸形请求；证明依赖确实参与认证、旧导出已移除及调用路径可用。现无测试脚本，执行阶段建立最小适用测试入口，记录实际命令和结果，不预先声称测试通过。

6. 最终集成 diff 和验证证据由 3 名独立只读审查者审查，关注正确性、迁移与安全边界；修复发现后重新审查受影响部分。未通过的必要门槛不得标记完成。
