## 批次、并行、等待与恢复

- 按模块、根因或验证面组织批次。先确定共享接口与依赖，再迁移模块，最后集成；批次冻结后运行受影响检查，在阶段边界运行必要的更广验证。保留真实断言、阈值和退出码。
- 仅在确有独立任务且收益超过协调成本时并行；为文件和职责设唯一写入 owner，共享接口、锁文件及生成文件也由单一 owner 负责。主执行者负责集成、接缝和最终验证。worker 不能覆盖或撤销他人的修改，worker 的测试不替代集成验证。
- 等待 CI、下载或审查时，推进下一模块只读调查、无冲突实现、迁移文档、失败分析或证据维护，不制造忙碌工作。
- 每项最多尝试 3 次，记录错误、证据、依赖和恢复条件；之后转为 waiting/deferred/needs-input，连同依赖项排到独立工作之后，在恢复条件变化或阶段边界重查。延期不豁免完成门槛。
- 修复/复审默认最多 3 轮；未解决问题保留未完成，不宣称通过。reviewer 必须独立于实现者且只读；所有 reviewer 检查集成 diff 和证据，可分别侧重正确性/测试、设计/边界、安全/可维护性。记录问题严重性、精确位置、证据、建议、处置和复审结果。
- reviewer 不可用时先完成无关工作，记录缺口和恢复条件，不用实现者自审替代 3 名独立 reviewer。
- 只有恢复、安全替代和独立工作均已穷尽，且所有有意义的剩余工作共同依赖同一已验证的强制外部依赖、安全边界或逻辑冲突，并满足当前宿主状态规则，才可整体 blocked。单项失败、排队、配额等待或单回合 3 次重试本身不足以整体停止。遵守用户明确暂停。
