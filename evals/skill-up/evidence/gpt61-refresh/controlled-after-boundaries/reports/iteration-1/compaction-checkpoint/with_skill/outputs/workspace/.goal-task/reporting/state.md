## 每轮执行、重试和等待

- 先核对本文件和 checkout，选择一个明确可验证的 batch；按模块、根因或验证面组织。定位根因及相关调用方，优先复用已有实现、标准库和依赖；所有修改必须对应已批准范围。
- batch 冻结后运行受影响验证；阶段边界运行适用的更广集成/包级验证。保留真实命令、退出码、断言、阈值和证据位置；历史绿灯不算当前证据，不通过削弱验证来过关。
- 每个 item 默认最多 3 次有依据的尝试；记录失败、证据、依赖与恢复条件，之后转 waiting / deferred / needs-input，并把它及依赖项放到独立工作之后。条件变化或阶段边界再检查；延期不豁免 gate。
- 等待时继续无冲突的后续模块只读调查、失败分析、验收准备或状态/证据维护。仅在明确独立且收益超过协调成本时并行实现，划清文件所有权，不覆盖其他人的改动。
- 降低并发或缩小 batch 应对资源压力；首次失败、可修测试、排队、配额及可选依赖不足均不自动终止整体目标。不忙轮询、不长时间前台 sleep、不虚构重置时间或自动唤醒。
- 只有所有有意义的剩余工作在恢复、替代和重排后共同依赖同一个经核实的必需外部依赖、安全边界或逻辑冲突，且满足当前宿主状态审计规则，才能报告整体 blocked。单轮重试 3 次不能替代跨 goal 轮次的宿主审计。用户明确暂停则遵循宿主暂停规则。

## 逐轮报告格式

每轮工作都报告，使用固定字段；阶段内完成项也要写出，不等到阶段完成：

```text
Progress: [□□□□□] 0/5 阶段完成（P0 基线、P1 payments、P2 orders、P3 reports、P4 集成）
This loop: 本轮实际完成项；验证命令/结果与证据；若产生里程碑 commit，写真实 hash 与该 commit 完成内容。
Remaining: 尚未通过的阶段/gates；等待项、失败和恢复条件。
Next: 一项明确的主要下一步。
```

按已通过的阶段将方格改为 ■；若展示百分比，只能用已完成阶段数 / 5，同时说明它是阶段计数。所有 gates 通过前不得报告 100%。每次里程碑 commit 后的下一次报告必须包含该 commit 和本轮完成内容。

## 独立审查与本地 commit

- 每个重要行为变更里程碑以及最终集成，都由 3 名独立只读 reviewer 检查实际 integrated diff 和验证证据；实现者与主 agent 自查不计独立 reviewer。必要时顺序安排，不要求 3 名同时在线。
- 审查覆盖正确性/测试、设计/边界、安全性/可维护性；每个发现记录严重性、准确位置、观察证据和建议。修复后复审受影响变更；默认最多 3 轮修复/复审，仍未解决的保留为未完成 gate 并重排，不能宣称完成。
- reviewer 不可用时先完成审查无关工作，记录 gate 与恢复条件，不能用实现者自审冒充独立审查。
- 相关验证与审查通过后创建非空本地里程碑 commit，记录真实 hash、完成内容及证据关联；不默认 push。不因赶 commit 丢弃高严重性发现或必需验证。
- 若不得不创建中间恢复性 checkpoint commit，明确列出未通过 gates，不将其当作通过里程碑。当前没有业务仓库，因此本次初始化不创建 commit。
