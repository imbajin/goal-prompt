```text
/goal 重构当前仓库的认证模块，使职责边界清晰、重复逻辑减少、认证策略集中且可测试，同时保持现有对外契约和安全语义兼容。自主完成必要判断与执行，无需再次确认。

当前信息：本次生成明确跳过仓库调查；认证实现位置、调用方、技术栈、验证命令和运行环境均未知，不得臆造。默认采用兼容性重构，不新增认证功能，不更换认证供应商，不主动改变公开接口、持久化格式或依赖体系。

范围：认证模块及完成重构必需的调用方适配、测试和文档。登录、登出、会话、令牌刷新、身份校验及权限边界仅按仓库实际存在的功能纳入。排除无关业务重构、界面改版和生产部署。

执行采用 Deep 模式：
1. 执行开始后读取适用的 AGENTS.md、贡献规则及现有权威设计，检查工作区变更；定位认证实现、调用链、公开契约、测试和 CI，建立行为与安全基线。优先复用现有实现、标准库和依赖，保护用户已有改动。
2. 在 .goal-task 下创建专用任务目录和非空 state.md，核实后将实际路径登记为执行与恢复入口；本目标生成时尚未初始化。状态记录基线、权威材料索引、范围、阶段、验收证据、评审、依赖、恢复条件及下一步。任务材料按最新用户要求、权威设计、任务清单、状态记录的顺序解释。
3. 依据真实调用关系选择最小必要结构调整，小步实施；每批运行受影响验证，阶段边界运行最小相关集成检查。修改公开契约或数据格式不属于默认兼容性重构；优先寻找范围内替代方案。
4. 每项最多尝试三次；仍失败则记录证据、依赖和恢复条件，将该项及依赖项排到独立工作之后。等待期间推进不冲突的测试准备、调用方核查、文档或证据整理；条件变化或阶段结束时复查，不能因此免除验收门槛。
5. 每轮有效推进后报告已完成、剩余门槛和一个下一步。上下文压缩、配额等待或交接前保存提交、未提交修改、验证与评审证据、等待项及恢复动作；恢复时核对当前工作区。只使用实际可用的恢复能力，不承诺不存在的自动唤醒。
6. 重大行为变更里程碑及最终集成均由三名独立只读评审者检查集成 diff 和证据，覆盖正确性、兼容性及安全性；实现者不计入。修复后复审，默认最多三轮；未解决项保留开放。评审能力不足时继续独立工作，记录缺口，不以自查替代。验证和适用评审通过后才创建非空本地里程碑提交；默认不推送。

授权：完成上述范围所必需、用户可授权的文件、依赖、环境和 Git 操作、测试、评审响应，以及确有必要的浏览器上传、使用已有凭据、推送和 PR 操作均已预授权，不因重复索取授权而停工。执行远程或破坏性操作前，必须从证据确定目标与影响并记录；范围外操作不获授权。此授权不创造凭据、会话、工具或能力，不覆盖宿主安全限制。不得展示、记录、截图、提交或发布凭据值。能力缺失时采用安全替代，继续独立工作并保留未满足门槛。

仅当以下条件全部满足才完成：
1. 重构后的职责和依赖边界有代码与调用方证据；现有公开接口、错误语义、会话和令牌生命周期及授权决策保持兼容，适用的撤销、过期、隔离和拒绝访问规则不被削弱。
2. 使用仓库真实存在的命令完成相关测试、静态检查和最小必要集成验证；针对实际改动补充有意义的回归测试，覆盖成功、失败和相关安全边界。记录命令、结果与基线差异，不以历史通过或生成测试代替本次验证。
3. 相关调用方均已适配，必要文档已更新；所有适用评审和复审通过，无未解决的阻断性问题。无法执行的必要验证必须保持未完成，不得宣称全部通过。
4. 持久状态与最终代码一致，交付说明包含改动结果、验证证据及实际剩余事项。

仅当恢复、替代方案和独立工作均已耗尽，所有有意义的剩余工作共同受制于同一已证实阻碍，且满足当前宿主的状态规则时，才报告整体 blocked。用户明确暂停或宿主强制停止时，保存检查点并如实报告未完成门槛。
```

采用 Deep 模式以覆盖认证兼容性、安全边界和分阶段评审。按要求未调查仓库、未创建初始化文件，也未启动重构；实际路径与验证命令留待执行时核实。
