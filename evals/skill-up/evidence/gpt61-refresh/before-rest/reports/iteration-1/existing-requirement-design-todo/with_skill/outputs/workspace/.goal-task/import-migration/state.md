## 执行约定

### 授权与能力

- 范围内必要且用户可授权的操作已获授权，不因常规权限提示再次询问、等待、延期或将整体标记为 `blocked`。授权不覆盖范围外操作，也不突破宿主权限，不虚构账号、凭据、工具或环境能力；证据中不得保存凭据值。
- 本任务只涉及本仓库迁移和验证，不引入部署、真实生产迁移、推送或远端 PR 操作。
- 首个执行循环检查实际需要的写文件、执行命令、独立审查、Git 提交和同目标恢复能力。当前代码区可写、命令可运行；网络受限但未发现必需网络步骤；当前宿主将 `.git` 列为只读，本地提交能力可能受限，须在执行时核实并保留该门槛。目标运行器的配额唤醒和原生恢复机制尚未验证。
- 若能力确实不可用，记录缺失能力、影响的门槛及可用替代路径，继续独立工作；不得伪造通过或用自审替代独立审查。

### 验证与证据

- 先检查已有实现、原生能力和已安装依赖。低风险改动按同一原因或验证面分批；每批运行相关测试，主要里程碑及最终集成后运行上述三个完整脚本。
- 增强现有测试以验证真实导入副作用、稳定拒绝码、已完成批次重放，以及中断后从持久化状态恢复。恢复用例须涵盖已产生副作用但尚未确认、检查点已持久化但尚未确认的失败窗口，证明有效记录无重复、无遗漏，确认前已保存完成检查点。
- 对既有输入和公开调用行为保留兼容证据。现有拒绝码基线若不可得，明确记录未满足项，不能凭新造码表宣称兼容。
- 不得削弱断言、跳过验证、忽略退出码或以占位检查替代行为证据。`typecheck` 原样运行并如实说明其空检查性质；不为制造绿色结果增改脚本或引入工具链。
- 最终证据关联具体提交或工作区 diff，记录命令、退出码、关键断言、持久化恢复方式和未验证项。修复后重跑受影响验证；最终 diff 变化会使相关旧证据失效。

### 等待、恢复与持续推进

- 单项默认最多尝试三次；仍失败则在原待办相应项记录错误、证据、恢复尝试、依赖和恢复条件。将其及依赖项排到独立工作之后，不降低验收要求；在阶段边界或条件变化时复查。
- 等待实现事实时，可整理已知兼容断言、审查现有测试缺口和准备验收矩阵；等待运行测试或审查时，可分析日志、维护证据与状态、检查非冲突部分。共享接口尚未核实时，不并行编造互不兼容的实现。
- 单项 `waiting`、`deferred` 或 `needs input` 不停止其他工作。整体 `blocked` 仅适用于：同一条件持续至少三个目标执行轮次，有限恢复和可用替代均已尝试、独立工作已完成，且所有有意义的剩余项共同受同一已核实的逻辑冲突、安全边界或必需外部依赖阻挡。三次重试不等于三个目标轮次。
- 每个有效循环后报告已通过门槛、当前完成和剩余内容、一个下一主动作。仅在门槛分母稳定时用准确比例；全通过前不得报告 100%。
- 每次阶段切换、上下文压缩、配额等待或会话交接前，更新基线/最新提交、变更路径、门槛比例、完成和剩余摘要、证据索引、等待依赖、产品批次恢复位置（如适用）及一个下一步；逐项状态只放原待办。
- 恢复时先读本文件和三份定稿，再核对 HEAD、工作区 diff、待办及证据版本；从已验证检查点继续，不凭聊天历史推测进度，不覆盖他人修改。
- 发生配额限制时保存未提交改动位置、当前状态及可核实的重置时间；优先使用经验证的原生非阻塞等待、唤醒和同目标恢复，不新建重复目标、不忙轮询、不虚构恢复命令。未知能力保留为待核实项。

### 审查、提交与结束

- 在主要行为变更里程碑及最终集成 diff 上安排恰好三名独立只读审查者；此仓库改动较小时三人分别审查完整 diff，覆盖正确性和测试、设计与公共边界、安全与可维护性。实现者自审不能替代独立审查。
- 修复后由独立审查者复审受影响部分，默认最多三轮修复/复审；仍未通过则记录并延期相关项，不宣称完成。审查必须没有未解决的高严重性问题；其他意见记录处理结论和依据。
- 主要里程碑产生持久修改时，在适用验证与审查通过后及时创建本地提交，默认不推送。仅用于恢复的中间检查点提交须列明风险及未通过门槛，不作为完成证据；纯只读工作不创建空提交。
- 不预建 lessons 文件；只有出现已验证、可复用的经验时才建立独立记录。
- 仅在最终目标的五项门槛全部满足时结束；最终报告包含实现结果、实际验证、审查结论、本地提交、剩余工作或明确无剩余项。收尾时更新本文件和原待办。
