## 执行契约

### 范围、授权与能力

- 只改与已确认迁移直接相关的文件，遵循已有实现与依赖，保留已确认接口、行为和数据兼容要求；范围外重构、技术选择和数据破坏不能由模块名称自行推导。
- 确认范围内所需且用户有权授权的操作均已预授权，包括环境/依赖/工作树/Git 操作、测试和审查；不得仅因授权提示再次提问、等待、延期或标记 blocked。未明确要求的 push 不默认执行；不得扩展到范围外。
- 对确有必要的破坏性或远程操作，执行前记录由证据确定的精确对象和影响；未明确对象先恢复事实。凭据仅可使用已有可用值，不暴露或写入日志、状态、证据、截图、提交及远程材料，仅记录脱敏操作和成败。
- 预授权不能创造凭据、工具、网络或文件权限，也不能覆盖宿主安全边界。当前宿主为 workspace-write、network restricted、approval never，无法通过申请提权解除；真实仓库不在可写根目录时使用允许的安全副本/工作树等可行替代，不能假装原仓库已改变。
- 首轮只预检实际需要的写入、命令、网络、Git、subagent、连接器和恢复/唤醒能力。遇到能力缺口，立即报告缺少什么、影响哪一门及可行调整，保留未通过门并继续独立工作。

### 分批实施与验证

- 先定位真实调用方、执行路径、公共接口和持久化边界，再分阶段实施；优先复用原生能力与已安装依赖。
- 以模块、根因或验证面组织小批次；批次冻结后跑受影响测试与定向检查，阶段边界和最终冻结后跑适用全量构建、检查与集成验收。保留必要边界验证，不编写仅复述实现的测试。
- 不削弱断言、不跳过必需检查、不忽略退出码、不把既有失败说成新结果。记录每条验证的命令、工作目录、revision、退出码/关键结果及证据位置。
- 默认按 payments → orders → reports 推进写入。等待中可以只读盘点下一模块、分析日志、整理验收证据和更新状态；只有依赖已满足且写入互不冲突时才并行实施。
- 独立子任务收益大于协调成本时使用 subagent；明确独占文件/职责、输入与输出及集成负责人；共享 schema、lockfile、生成文件等只允许一名写入负责人。告知所有执行者并非独占仓库，不得覆盖或回退他人变更。集成后重跑受影响验证。

### 独立审查与里程碑提交

- 每个中间重要行为迁移里程碑及最终重要里程碑，恰好使用 3 名独立只读审查者。审查者不可同时是该变更的实施者；先看全局风险，再分别聚焦正确性/测试、设计/边界、安全/可维护性。小 diff 由 3 人各自完整审查。
- 审查最终整合 diff 与验证证据；修复后对受影响变更复审，默认最多 3 轮修复/复审。未解决高严重性问题或失败门不能被宣布通过。
- 若审查能力不可用，尽早报告风险，完成不依赖审查的工作并将该门记录为 needs input；自查不能替代独立审查，也不自动让整个目标 blocked。
- 验证与适用审查通过后立即创建本地里程碑 commit，只提交本任务相关变更，不覆盖用户改动，不制造空提交，不默认 push。必要风险检查点提交不代表验收通过，必须标明未通过门。
- 每次重要里程碑提交后更新本文件；下一次进度报告必须给出 commit hash、该提交完成的内容及本轮结果。不得把提交成功等同于功能验证成功。

### 每轮报告与状态维护

每个工作轮结束都报告以下格式；长时间执行中持续给出简短进展，不能仅在最后总结：

```text
Progress [████░░░░░░] 40% (2/5 gates)
This loop: 本轮完成项、关键验证证据；如有里程碑提交，写明 commit hash 与完成内容。
Remaining: 未通过门、关键剩余项、等待/延期及依赖。
Next: 一个主要下一步。
```

百分比严格对应已通过门；只有所有门通过才允许 100%。每轮更新当前阶段、完成/剩余项、有效证据、最新 commit、未提交变更、等待/延期、依赖及下一步。真实学习简记即可，只有有证据的可复用经验才创建 lessons.md。

### 失败、等待及停止

- 同一事项默认最多尝试 3 次；失败后记录错误、证据、已尝试恢复及依赖，标记 waiting/deferred/needs input，并将该项及其依赖移到独立工作之后。阶段边界或解锁条件变化时重查，不豁免验收门。
- 构建、测试、CI、下载和环境等待时继续有价值的不冲突任务，例如下一模块只读盘点、日志分析、验收准备和状态维护；不制造忙碌。资源紧张时先减并发、缩批次、调整验证节奏，再尝试已授权替代资源。
- 单项失败、网络抖动、排队、配额或输入缺失均不自动停止整体目标。整体 blocked 只在同一阻碍跨至少 3 个连续 goal turn 持续存在，且恢复、替代、拆分、重排与所有独立工作均已穷尽后，所有实质剩余事项仍共同依赖同一逻辑冲突、安全边界或已核实必需外部依赖时设置；3 次重试不等于 3 个 goal turn。

### Compaction、配额及交接

- compaction、配额等待或交接前，必须先写入当前 gate 百分比、完成项、剩余项、最新 commit、验证及审查证据、未提交变更、活动等待/延期、依赖与一个主要下一步；新会话先读本文件即可恢复，不依赖重建聊天历史。
- 配额敏感工作前核实原生检查点、非阻塞等待/唤醒和同一 goal 恢复能力。耗尽时记录失败与可核实的重置时间及其时区/来源；未知则明确未知，不能编造恢复时间或命令。
- 优先原生非阻塞恢复同一 goal，不创建重复 goal、不忙轮询、不用长前台 sleep。只有原生恢复不足才考虑本地 helper，且必须支持 dry-run、明确时区、幂等检查点及已验证唤醒机制。
