## 调度、验证、重试与审查

- worker 等待额度时，立即把该项及依赖它的结论排在 api 静态核查、api 报告、worker 可读资料整理、已完成证据审查之后，不让 worker 等待阻断 api。
- 每轮围绕模块或证据面形成可审查批次。只运行已从实际仓库确认且与该批相关的验证；记录命令原文、基线、环境、结果和局限。未执行、失败、历史记录均如实标注，不声称全部测试通过。
- 每项最多 3 次有依据的尝试；同一未改变的额度条件不反复请求。记录错误、证据、次数、依赖和恢复条件，然后将 waiting/deferred/needs-input 项后移；仅在条件变化或阶段边界有依据时复核，不忙轮询、不循环长时间前台睡眠。
- 纯证据任务采用 1 名独立只读证据审查者，不使用业务实现审查门禁。问题须含严重性、准确位置、观察证据和建议。修订后复审受影响部分；默认最多 3 轮，仍有未解决的必要问题则保留门禁，不能宣称完成。审查能力不可用时继续无关工作，记录缺口，不能用作者自审替代独立审查。
- 若并行执行，只有确实独立且有收益的 lane 才分派；api、worker 产出须划定互斥写入责任。主执行者独占本文件与最终汇总报告的整合写入。不得覆盖他人改动，独立审查者不得参与被审产出。
- 每个有效循环后报告已完成内容及证据、剩余门禁和一个首要下一步。没有明确且稳定的分母不报百分比；所有门禁通过前不能报告 100%。
