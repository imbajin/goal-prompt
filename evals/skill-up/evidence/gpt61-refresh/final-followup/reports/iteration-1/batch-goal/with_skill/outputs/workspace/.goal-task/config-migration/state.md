- 真相顺序：最新用户确认 > 已批准清单及权威迁移规范 > 仓库任务材料 > 本状态文件；上层宿主指令始终优先。
- 本文件管理执行约定、阶段证据、恢复和逐项状态；固定 8 项无需额外 todo.md。模块身份未知时不编造条目。
- 已确认范围内必要且用户可授权的操作已预授权，包括文件、依赖、环境和 Git 操作、测试、审查响应，以及确有任务必要性的上传、使用已有凭据、推送和 PR；不得因重复索取授权而停工。执行前从证据确定远程或破坏性操作的目标和影响；默认仅本地提交，不主动推送。授权不创造能力、不越过宿主安全边界、不覆盖范围外工作；不得披露或持久化凭据值。

## 执行、变更检测与逐项记录

- 冻结批准的集合和源配置基线后，逐模块形成迁移、验证、审查和证据闭环；按共享模块、根因或验证面安排工作，不扩大到清单外模块。
- 对每项在开始、恢复和提交前核对清单成员及模块源配置；记录自身预期迁移 diff，以区分任务内修改与外部或无法解释的漂移。
- 任一固定模块消失、成员身份变化或内容相对批准基线出现未授权变化：立即暂停该项及真正依赖它的工作，记录时间、模块身份、缺失路径或脱敏差异、前后摘要/哈希、相关版本和影响。清单消失或无法确认集合时暂停所有依赖集合的迁移。不得替换模块、自动接受新基线或通过重试覆盖漂移；保留原门槛，只有恢复原批准材料或用户明确批准变更后才恢复该项。
- 每项记录：原始身份及路径、基线证据、当前状态、迁移差异和语义对应关系、验证命令/退出码/脱敏输出、审查结果、依赖与恢复条件、下一步。当前没有可核实的模块身份，逐项台账尚未建立。
- 除上述立即暂停情形外，同一问题最多尝试 3 次；记录失败与恢复条件，把等待、延期或需输入项及其依赖移到独立工作之后。恢复条件变化或阶段边界再核查，不无限轮询，不免除完成门槛。
- 等待时继续其余固定模块的安全只读检查、无冲突迁移、失败分析、证据整理或验收准备；不得修改同一组共享文件造成冲突。没有有用的独立工作时如实记录，不制造忙碌。

## 阶段与合取完成门槛

1. 基线准备：原批准 8 项可追溯，迁移要求、调用方、验证入口已核实。
2. 逐模块迁移：8 项均按权威要求完成配置转换，保持要求保留的语义、接口和兼容性；每项通过真实 `validate-module`，保存针对最终改动的执行证据。受影响调用路径及边界行为有与风险相称的验证。
3. 重大行为变化里程碑审查：每个模块或共享转换机制形成重大行为变化里程碑时，3 名独立只读审查者检查当时集成 diff 与证据；实施者不计入。修复问题后复审受影响部分；默认最多 3 轮修复/复审，仍有问题则延期并保留门槛。
4. 最终集成：全部 8 项完成后运行真实 `validate-all`；修复后重跑受影响的逐模块验证和最终集成验证，确保绿色证据对应最终版本。3 名独立只读审查者检查最终集成 diff 与证据，修复后复审。审查能力不足时保留未满足门槛，不能用实施者自查代替。
5. 交付：必要的现有配置文档与最终行为一致；本文件包含逐项结果、命令/结果、兼容性与迁移证据、审查结论和剩余事项。只有所有门槛同时满足才可宣布完成，暂停项仍计入未完成范围。

## 检查点、提交与整体阻塞

- 每个有效循环后记录并报告已完成证据、剩余门槛和一个下一步；集合身份核实前不报告比例，冻结后也不能在全部门槛通过前报告 100%。
- 每项及阶段边界、上下文压缩、配额等待或交接前保存检查点：完成/剩余、最新提交、未提交改动、验证/审查证据、活动等待、恢复条件和一个下一步。恢复先将本文件与真实仓库及证据核对，不从聊天猜测状态。
- 适用验证及审查通过后本地提交持久里程碑；无空提交，默认不推送。必要的中间检查点必须注明未通过门槛。不得为提交移除必需验证或隐瞒问题。
- 能力缺失时保持相关门槛开放并推进独立工作；配额耗尽时保存检查点、已知恢复时间（如可验证）和准确下一步，不虚构重置时间、状态 API、唤醒或恢复命令。
- 单项暂停不等于整体阻塞。只有恢复尝试、安全替代和独立工作均耗尽，所有有意义的剩余工作共同依赖同一个已核实的必需外部依赖、安全边界或逻辑冲突，并满足当前宿主状态规则时，才可报告整体 blocked；若宿主要求连续目标轮次证明，同轮 3 次重试不能替代。
