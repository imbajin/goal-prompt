## 执行顺序与独立工作

按证据核实业务规则和当前差距，优先复用现有实现、标准库、原生能力和已安装依赖，再实施最小必要修改；依赖变动必须有任务依据。所有修改均应对应账户导入请求。

工作链：真实上下文与目标解析 → 导入调用链和必要依赖修改 → 有效测试与本地验证 → 实际浏览器功能及 UI/UX 验收 → 独立审查与复审 → 合规提交、push、PR → 远程 CI 与 PR review 处理。可提前运行测试；push/PR 后仍须执行和跟踪适用检查，最终证据对应最新提交。

浏览器或会话等待时，继续解析/校验和导入逻辑、错误处理、相关自动化测试、接口核查及验收准备；CI 等待时，继续分析已有日志、整理脱敏证据、准备 review 和 PR 材料；review 等待时，继续无冲突的验证和文档。只做有实际价值的工作，不为并行制造工作。缺少整个仓库时，仍可维护契约、列明真实缺口和准备验收，但不得凭空构造项目实现。

独立工作在收益超过协调成本时拆分。主执行 agent 负责集成与最终 diff；每条实现线明确输入、输出和独占文件所有权，锁文件、schema、生成文件等共享写点仅有一个负责人。明确告知参与者并非独自在仓库工作，不得撤销他人修改。集成后重跑受影响检查，单条线通过不等于集成通过。

## 独立审查与提交/PR

每个中间主要行为里程碑与最终主要里程碑均使用恰好 3 名独立只读 reviewer。小改动各自审查完整集成 diff；大改动先各自扫描全局风险，再分别重点审查正确性/测试、设计/边界、安全/可维护性。实现者自查不能替代独立审查。

修复后对受影响改动复审，默认至多 3 轮修复/复审。仍未通过则记录、延期受影响工作并继续独立事项，不能宣告完成。reviewer 不可用时，记录缺失的必需审查和恢复条件，完成不依赖 review 的工作，保留审查门槛。

主要里程碑产生持久仓库修改后，在适用验证和审查通过后及时提交，不创建空提交。必要基线可创建标明风险与未通过门槛的中间 checkpoint commit，但不代表通过 review 或完成。记录提交及证据覆盖范围。

本任务明确要求 push 和创建 PR，覆盖默认不 push 的规则；核实目标后推进。PR 描述说明最终问题、行为和验证，保留真实限制。跟踪并处理远程 CI 和 review，修复后重新验证、复审、提交和更新 PR；最终所有证据对应最终提交。创建 PR 不意味着任务完成，也不授权合并或部署。

## 重试、恢复与停止

同一项默认最多尝试 3 次。失败后记录错误、证据、恢复尝试和依赖，将该项标为 waiting/deferred/needs input 并连同依赖项排到独立工作之后；阶段边界或解除条件变化时复查。不因普通失败、CI 排队、可修复测试错误、临时网络错误或配额等待停止整体目标。

资源不足时先降低并行度、缩小批次、调整验证节奏，再用已授权的可用替代资源；无法完成的项保留门槛。授权提示本身不能作为延期原因，真实能力限制应如实记录。

只有在有界恢复、安全替代、拆分、重排和全部独立工作完成后，所有有意义的剩余工作仍共同依赖同一已核实的逻辑冲突、安全边界或强制外部依赖，且同一条件连续至少 3 个目标轮次出现，才可按原生规则将整体设为 blocked。单项 3 次重试不等于 3 个目标轮次；没有原生目标状态工具时不声称已调用或设置状态。门槛未过不得宣告 complete。
