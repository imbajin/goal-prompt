## 执行合同

- 仅修改能对应三模块迁移的代码、相关调用方、测试和必要文档；保留用户已有改动，优先复用已有实现、标准库和依赖。范围外改动未经授权。
- 范围内用户可授权的必要操作均已预授权，包括本地／环境／依赖／Git 和 worktree 操作、测试、review 响应，以及确有任务需要且目标已确定的远程／PR 操作、浏览器上传和已有凭据的使用。不得仅因通常需要授权而再问、等待、延期或标记整体 blocked；这不覆盖宿主限制，不创造凭据或能力。
- 默认仅创建本地 commit，不 push，不擅自部署或改变线上数据。远程或破坏性操作如确属确认范围，必须先记录准确目标与影响；若多个实质不同目标无法判定，仅解决范围选择，不能把范围选择当作重复授权。
- 不在日志、截图、状态、commit、PR 或证据中暴露／持久化凭据值，只记录脱敏动作与结果。真实能力缺口使用安全替代，保留未通过门禁并继续独立工作。

### 工作轮次、验证与并行

- 按模块、根因或共享验证面冻结低风险批次，再运行受影响测试与必要静态检查；阶段边界或最终 diff 冻结后运行仓库要求的构建、包检查与集成验证。命令必须取自实际仓库政策／脚本，不虚构成功，不弱化断言、不跳过必需检查或忽略退出码。
- 公共接口、持久化数据或风险边界扩大时拆小批次，先核实相关调用链。接口／schema／依赖的实质性越界变化保持未批准状态，不擅自扩大范围。
- 有实质等待时推进独立工作：下一模块只读调用方／测试盘点、验收准备、失败日志分析、证据与状态维护；共享契约未稳定前不开始依赖它的实现。若确认独立且收益超过成本，可并行实施；每位 worker 独占文件与责任，共享 schema／lockfile 等由单一集成负责人持有。不得撤回他人改动。
- 集成负责人拥有最终 diff；并行结果合并后重跑受影响检查，单模块通过不等于跨模块通过。

### 独立审查

- 深度迁移的每个中间重要里程碑及最终重要里程碑，必须由恰好 3 位独立只读 reviewer 审查集成后的 diff 和证据；实施者自查不替代审查。
- 大改动：3 人先扫描全局风险，再分别侧重正确性／测试、设计／边界、安全／可维护性；小批次则 3 人各自审查完整变更。
- 修复后对受影响变更复审；默认最多 3 轮修复／复审。未解决高严重性问题、失败测试或其他未通过门禁时不得宣布完成或作为已通过里程碑提交。
- reviewer 不可用时尽早记录能力风险，完成不依赖审查的工作，相关项保留 needs input；不得用实施者自审代替，也不得自动整体 blocked。

### 重试、延期与整体停止

- 单项默认最多尝试 3 次；仍失败就记录错误、证据、恢复动作、依赖及解除条件，标为 waiting／deferred／needs input，将该项及依赖项排到独立工作之后；在阶段边界或解除条件变化时复查。不豁免验收。
- payments 等待时可准备 orders、reports 的调用方清单与验收；orders 等待时可推进不依赖它的 reports 工作、payments 证据；reports 等待时可处理前两模块的回归与文档。是否独立由实际依赖证据决定。
- 资源紧张先减并发、缩批次、调整验证节奏、使用已授权且可用的替代资源，再延期受影响项。首次失败、网络瞬断、CI 队列、普通缺问、配额等待都不是整体停止条件。
- 仅当同一阻碍连续至少 3 个 goal turn 重现（不同于单项 3 次重试），且有界恢复、替代路径、拆分、重排及全部独立工作完成后，每个有意义的剩余项仍共同依赖同一已验证逻辑冲突、安全边界或必需外部依赖，才可整体 blocked。保留未通过门禁；不得因等待项停止其他工作。
